




## 初始化工程

```bash
# 创建一个项目目录，然后运行初始化命令。
mkdir project
cd project
# 我们将使用域名 tutorial.kubebuilder.io，
# 所有 API 组将为 <group>.tutorial.kubebuilder.io。
kubebuilder init --domain github.com --repo github.com/cronjob --repo cronjob

```

您项目的名称默认为您当前工作目录的名称。您可以通过传递 --project-name=<dns1123-label-string> 来设置不同的项目名称。

如果您的项目在 GOPATH 内初始化，则隐式调用的 go mod init 将为您插入模块路径。否则，必须设置 --repo=<module path>。



## 创建API

添加一个新的API，要创建一个新的Kind，以及相应的控制器，我们可以使用Kubebuilder create api

```bash
kubebuilder create api --group batch --version v1 --kind CronJob
```

## RBAC

大多数控制器最终都会在集群上运行，因此需要 RBAC 权限，我们使用 controller-tools 的 RBAC 标记来指定这些权限。这些是运行所需的最低权限。随着功能的增加，我们将需要重新评估这些权限。

```go
// +kubebuilder:rbac:groups=batch.tutorial.kubebuilder.io,resources=cronjobs,verbs=get;list;watch;create;update;patch;delete
// +kubebuilder:rbac:groups=batch.tutorial.kubebuilder.io,resources=cronjobs/status,verbs=get;update;patch
```
config/rbac/role.yaml 中的 ClusterRole 清单是通过 controller-gen 使用以下命令，根据上述标记生成的：

```bash
// make manifests
```


## 创建控制器

```bash
kubebuilder create webhook --group batch --version v1 --kind CronJob --defaulting --programmatic-validation
```
